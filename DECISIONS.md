## Phase 1: Schema and game engine

- **2026-10-10 · Roles inside migrations.** Migration 0002 creates `eyeq_owner` (nologin), `eyeq_api` and `eyeq_service`, grants `eyeq_owner` to the migration user, and every later migration runs `set role eyeq_owner`, so all objects are owned by it (plan 5.3). Login passwords are never set by a migration; locally `db/seed` does not set them either, since tests switch role inside the admin session. Phase 2 sets them from Key Vault.
- **2026-10-10 · Seeded rules are active from 2000-01-01.** `game_config` rows from `db/seed/game_config.json` carry a fixed `active_from` so re-seeding updates in place and historical evaluations (a rollover for a past week, a late sync) find a value. A real rule change is a new row with a later `active_from`.
- **2026-10-10 · Streak is a query over facts.** `streak_run`, `current_streak` and `best_streak` are gaps-and-islands queries over `session_completions` (counting) and `freeze_ledger` 'used' rows (holding), never a counter. `settle_missed_days` judges each unjudged day in order and consumes a freeze only if one was held _at the end of that day_ in fact time (`freezes_held_at`): a freeze bought after a missed day cannot cover it. `streak_close` calls it for yesterday; `complete_drill` calls it for the days before the completion so a held freeze bridges the gap before the multiplier is computed.
- **2026-10-10 · Session kinds.** `session_completions.session_id` is nullable with `free_drill_id` as the alternative, so the free tier's daily drill (deterministic per date via `free_drill_of_day`) can be the day's session (D20). A drill completed outside a session and not the day's free drill earns drill XP only.
- **2026-10-10 · Sessions carry `program_id`.** Denormalised beside `module_id` with `unique (program_id, day_number)`, so "the session for `current_day`" is one lookup.
- **2026-10-10 · Entitlement guard.** A deferred constraint trigger refuses any `entitlements` insert or update unless the newest `entitlement_events` row's snapshot matches the row's status, starts_at and ends_at at commit time. `grant_entitlement`, `set_entitlement_status` and `end_entitlement` are the only writers. `entitlement_events` has a `seq` identity column so "newest" is unambiguous within a transaction.
- **2026-10-10 · Balance guards twice.** `spend_coins` locks the athlete's `user_stats` row so concurrent spends serialise (verified by a two-connection vitest integration test), and a constraint trigger on each ledger refuses a negative sum regardless of the caller.
- **2026-10-10 · Leaderboard ranks.** Rank = 1 + number of public athletes strictly ahead (higher XP, then earlier `last_xp_at`, then user id). A private athlete therefore has a rank of their own and is never listed (plan 6.6). `rank_day_start` is a snapshot at 00:00 IST but is also rebuildable: `rebuild_leaderboards` recomputes it from the ledger as of the day start.
- **2026-10-10 · Badge and challenge rules share one evaluator.** `metric_value(user, rule, window)` with `gte`/`lte` and the metrics listed in plan 6.7, plus `module_sessions` (progress = sessions done in a module, target = sessions in it) for "Finish Module 2 by Sunday", and `drill_count`. Weekly-only metrics (`weekly_rank_lte`) are evaluated by `week_rollover` through `evaluated_on = 'weekly'`.
- **2026-10-10 · Level-up coins per level crossed.** A session that crosses two levels pays 2 × `xp.level_up_coins`. Frames on a new title are phase 10.
- **2026-10-10 · Notification text is not stored.** `notifications` holds kind, channel and `data`; the worker renders copy through `packages/i18n` (rule 16). The 2-a-day push cap is applied at enqueue time (a third is inserted as `skipped` with `last_error = 'daily_cap'`) so the record exists even if the worker never looks.
- **2026-10-10 · Seed placeholders (D2, D21, D24).** Badge coins without a source: Three Days In 10, Three-Week Flame 40, Scan Master II 50, Early Bird 20, Five-a-Week 20, Module Clear 20, Top 3 30, First Rep 10. Product prices: Pro 299/799/2,499, programs 999/1,299/799, credits 499, pay-per-view drill 99 (rupees, tax inclusive, placeholders). Drill video refs are placeholders. Arjun's totals are normalised to 2,040 XP and 140 coins after the challenge pass; which weekly challenge rows are complete at seed time depends on the weekday the seed runs.
- **2026-10-10 · The seed is not re-runnable.** Ledgers are append-only, so `pnpm db:seed` refuses to run when demo data exists: `pnpm db:reset && pnpm db:seed`.
- **2026-10-10 · pgTAP tests are plpgsql functions.** The Node runner cannot interpret psql meta-commands (`\gset`), so each file defines `pg_temp.t()` returning `setof text`. Before every file the runner seeds config, loads `packages/game/vectors/*.json` into `test_vectors`, and runs `db/tests/_*.sql` preludes. Tests avoid the current ISO week where seed data could interfere, so the suite passes on a seeded or an empty database.
- **2026-10-10 · Rules the sources left undefined, decided here.** (a) The multiplier uses the streak as of the day before the completion's local date, from facts, also for late completions. (b) A repeat drill the same day returns `amount 0` with `repeat: true` in the result. (c) The first logged score of a drill sets the mark; a personal best pays once per drill per day. (d) `completed_at` more than 5 minutes in the future is clamped to receipt time. (e) `enroll` requires access; enrolling in another program deactivates the current one but keeps its progress. (f) A session replayed after the enrolment has moved on does not move `current_day` backwards. (g) Program completion XP is paid once per program, on the last session. (h) The at-risk state needs `streak.at_risk_min_streak` (3) and the nudge time; `ended` is shown for 7 days after the last trained day.

- **2026-10-11 · The athlete API for the loop (section 7).** `GET /home`, `GET /drills/:id`, `GET /drills/:id/media?session=`, `POST /completions`, `GET /progress`, `POST /me/self-ratings`, `POST /programs/:id/enroll`, `GET /me/entitlements`, all on `apiRoute()` with contracts in `packages/api-contract/src/daily.ts`. Payloads come from the phase 1 SQL functions, camelized and parsed against strict contracts like the phase 4 reads. `GET /drills/:id` is not in the plan's list: the free drill of the day (D20) is not part of a session, so the player needs a way to read it.
- **2026-10-11 · `POST /completions` takes a batch and needs no Idempotency-Key.** Up to 20 events, each idempotent by its `client_event_id` inside `complete_drill` (rule 6), each under its own savepoint so a refused event (a locked drill) is reported alone and the rest commit; the mobile offline replay (phase 8) uses the same call. Rate limited by the existing `completions` rule (30 a minute) as well as the per-athlete API limit.
- **2026-10-11 · Analytics after commit.** `apiRoute()` gained `afterCommit`, called once the transaction has committed and never for a replayed result. The completion route uses it with Next.js `after()` to send `drill_completed`, `session_completed` and `streak_extended`, skipping results `complete_drill` marks as duplicates. Properties are about the training (drill id, session kind, XP, streak), never the person (rule 11).
- **2026-10-11 · Engine errors reach clients as codes.** The SQL raises `P0002` (not found), `P0003` (locked) and `P0004` (wrong state) with a snake_case reason; they map to 404 `not_found`, 403 `locked` (new) and 409 `conflict` (new), with `details.reason`. Prisma 7 wraps them in its own `P2010` with the SQLSTATE at `meta.driverAdapterError.cause.code`; `sqlState()` now searches the wrappers and ignores Prisma's own `P1xxx`–`P6xxx` codes. Before this, every such error was a 500.
